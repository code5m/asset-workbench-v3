# Evidence-driven framework evolution

- Source: chatgpt
- Capture Mode: agent-work-record
- Related conversation evidence: transcript_chatgpt_20261007_framework_asset_core_ssot

## Task

Turn the user's higher-stage framework vision into a governed architecture rule and
make the discussion itself a durable project asset.

## Context

The user clarified that Asset Workbench should evolve through real project
management rather than be treated as a static scaffold. Multiple project
experiences and conversations should reveal reusable problems, which can then be
validated, generalized, released, and distributed back to applicable projects.

The user also explicitly requested that important ChatGPT conversations and
decisions be written into the project for later review and reflection.

## Investigation

- Reviewed current AGENTS knowledge-capture rules.
- Reviewed existing Decisions 0003–0005.
- Reviewed Framework page beginner and advanced architecture sections.
- Confirmed there was no formal cross-project framework-evolution governance
  model yet.
- Confirmed existing conversation evidence can be safely extended as partial/manual
  ChatGPT evidence.

## Findings

1. Real projects should be treated as practice sites that teach the framework.
2. Project-specific exceptions must remain local by default.
3. Repetition is evidence, not automatic permission to modify Core.
4. A reusable change needs an explicit Framework Candidate stage before entering
   shared Core.
5. Distribution to projects should become version/capability/schema/rule based,
   not full-repository copying.
6. RSI is a future governed objective, not permission for ungated self-modification.
7. The user considers the reasoning path itself a reflection asset, not just the
   final code change.

## Changes

- Added an advanced collapsed Framework-page section explaining the evolution loop.
- Added bilingual evolution terminology.
- Added AGENTS anti-regression governance.
- Added a formal framework-evolution Design.
- Added Decision 0006 adopting Evidence-Driven Framework Evolution.
- Appended the current real conversation excerpts to partial ChatGPT evidence.
- Added regression tests and documentation updates.

## Verification

- Full repository CI required before merge.
- UI tests verify the advanced evolution section and bilingual copy.
- Governance tests verify AGENTS contains the project-local default and the
  controlled promotion funnel.
- No runtime distribution/adoption automation is claimed in this change.

## Outcome

The project now has a durable model for learning from multiple real projects while
protecting shared Core from one-off project exceptions.

## Follow-up

Future capabilities may implement:

- Framework Candidate records;
- cross-project pattern aggregation;
- framework capability/schema versions;
- project adoption state;
- migrations and rollback;
- distribution automation;
- eventually governed RSI workflows.

Each of those future capabilities must themselves pass through the adopted
evolution funnel.
